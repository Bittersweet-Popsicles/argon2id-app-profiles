# 상용 애플리케이션 설정에 따른 Argon2id GPU 구현 비교

Private Photo Vault, Threema, LunaCam에서 확인한 Argon2id 설정을 바탕으로 두 PC에서 다섯 가지 GPU 구현 구성의 처리량을 비교했습니다. 이 저장소에는 측정 기록과 논문 표 6 및 표 9를 다시 계산하는 코드가 들어 있습니다.

| 목적 | 필요한 자료 | 확인할 수 있는 결과 |
|---|---|---|
| 표 6과 표 9 재계산 | 이 저장소와 Python 3 | 두 환경의 구현 순위, 환경 A의 선택을 B에 적용했을 때의 처리량 차이, 환경 A의 CPU 대비 GPU 처리량 비율 |
| 보조 실험 결과 열람 | 저장소의 CSV 파일 | 환경 B의 CPU 기준선, 환경 A의 배치 및 CUDA/CuPy 버전별 집계값 |
| 다른 GPU에서 공통 배치 32 실험 재측정 | 별도 Windows용 실험 키트와 호환 GPU 환경 | 해당 PC의 새 시간 표본과 CPU 참조 출력 대조 결과 |

## 저장소에서 표 6과 표 9 재계산하기

저장소 최상위 폴더에서 다음 명령을 실행해 주세요. Python 표준 라이브러리와 로컬 파일만 사용하므로 GPU, Visual Studio 또는 추가 패키지 설치 없이 실행할 수 있습니다. Python 3.14.8에서 실행을 확인했습니다.

```sh
python reproduce.py
```

스크립트는 `checksums.json`을 기준으로 입력 파일의 SHA-256을 대조하고, 조건별 시간 표본의 누락과 중복을 확인한 뒤 결과를 출력합니다.

**표 6. 두 환경의 구현 순위와 선택에 따른 처리량 차이**

세 앱 설정과 두 salt 조건을 조합한 여섯 조건을 비교합니다. 구현별로 다섯 세션의 측정 시간 25개를 모은 뒤, 배치 크기 32를 시간의 중앙값(초)으로 나누어 초당 처리량을 계산합니다. 마지막 열은 환경 A의 최상위 구성을 환경 B에서도 사용했을 때, 환경 B의 최고 처리량 대비 차이를 나타냅니다. 다섯 조건에서는 0.00%이며, LunaCam의 후보별 salt 조건에서는 −0.36%입니다.

**표 9. 환경 A의 CPU 대비 GPU 처리량 비율**

환경 A에서 CPU로 후보를 한 개씩 처리했을 때와 GPU 구성 #1로 54개씩 처리했을 때의 초당 처리량을 비교합니다. 반올림 전 집계값으로 계산한 비율은 Private Photo Vault 17.17배, Threema 24.00배, LunaCam 26.03배입니다.

## 수록 자료

| 파일 | 내용 |
|---|---|
| `data/protocol.json` | 공통 배치 32 실험의 앱별 파라미터, salt 조건, 준비 및 측정 횟수, GPU 유휴 기준을 기록했습니다. |
| `data/timings.csv` | 환경별 주 실험 150개와 salt 길이 보조 실험 25개에서 각각 5회 측정한 시간입니다. 두 환경 합계 1,750개 표본이며 단위는 초입니다. |
| `data/cpu-a.csv`, `data/cpu-b.csv` | 두 환경의 CPU 단일 후보 처리량을 기록했습니다. 표 9에는 환경 A의 값을 사용합니다. |
| `data/additional-a.csv` | 환경 A의 추가 실험 집계값입니다. 표 9의 GPU 값은 `phase=main`, `mode=fixed`, `batch=54`, `config=1`인 행에서 확인하실 수 있습니다. |
| `data/cuda-a.csv`, `data/cupy-a.csv` | 환경 A에서 각각 수행한 CUDA 및 CuPy 버전 비교 결과를 확인하실 수 있습니다. |

원 실험에서는 환경 A에 RTX 4070 SUPER, 환경 B에 RTX 4060 Ti 8GB를 사용했습니다. 두 환경의 공통 소프트웨어 구성은 Python 3.14.7, NumPy 2.4.4, CuPy 14.2.0입니다. 준비 이후 동기화된 KDF 배치 호출이 완료되기까지의 시간을 측정했으며 입력 전송과 결과 반환을 포함합니다. 원 실험에서는 준비 호출을 포함해 환경별 39,200개 출력을 CPU 참조값과 대조했습니다. 저장소의 스크립트는 당시 기록한 시간 표본과 집계값을 읽습니다.

## 다른 GPU에서 공통 배치 32 실험 재측정하기

새 측정에는 별도 Windows용 실험 키트 `Argon2id_공통조건32_전체패키지_2026-11-05.zip`이 필요합니다. 키트를 확보하신 후 아래 SHA-256을 확인하고, 상위 경로까지 영문인 폴더(예: `C:\Argon2id`)에 압축을 풀어 주세요.

```text
90b892aa5df5b0c56c63ba2a0ff996ea394e4a684c6c0d9419436f535a3ef74e
```

### Visual Studio 빌드 환경 준비하기

새 PC에서 GPU 구성 #2~#5의 CUDA DLL을 빌드할 때에는 MSVC와 Windows SDK가 필요합니다. RTX 4060 Ti PC에서는 Visual Studio 2026 Community에 다음 구성 요소를 설치한 뒤 빌드 도구 검사를 통과했습니다.

1. Visual Studio Installer에서 Visual Studio 2026을 설치하거나, 이미 설치한 경우 **수정**을 선택해 주세요.
2. **C++를 사용한 데스크톱 개발** 워크로드를 선택해 주세요. **개별 구성 요소**에서 **MSVC v142 - VS 2019 C++ x64/x86 빌드 도구(v14.29)** 및 **Windows 11 SDK (10.0.22621.0)**를 추가해 주세요. 항목명의 “VS 2019”는 Visual Studio 2026에 추가하는 도구집합을 가리킵니다. 키트에서 선택하는 도구집합 버전은 `14.29.30133`, 컴파일러 버전은 `19.29.30159`입니다.
3. 외부 DLL 빌드에 사용하는 **CUDA Toolkit 11.8**을 기본 경로에 설치해 주세요.
4. 새 PowerShell을 열고 **압축을 푼 키트의 최상위 폴더**에서 다음 명령을 실행해 주세요.

```powershell
python development/portable_argon2/common32_study.py --check-build-tools
```

`BUILD TOOLS OK`와 함께 MSVC 및 SDK 버전, `cl.exe` 경로가 출력되면 키트에 포함된 `README_COMMON32.md`의 준비 및 실행 절차를 따라 주세요. 이전 실행 명령에서 Visual Studio 2022를 찾는 오류가 표시되었다면 위의 공통 배치 32 전용 명령으로 다시 확인해 주세요. 이 명령에서도 컴파일러를 찾지 못하면 Installer에서 Visual Studio 2026에 v142와 지정 SDK가 설치되어 있는지 확인해 주세요.

## GPU 구현 출처

구성 #1은 연구에서 사용한 자체 CuPy 기반 구현입니다. 구성 #2~#5는 Mosnáček의 공개 구현 계열이며, 구성 #3과 #5는 같은 소스에서 참조 인덱스 사전계산 옵션을 달리했습니다. [Mosnáček의 argon2-gpu 공개 저장소](https://gitlab.com/omos/argon2-gpu)
